# CPU의 구조

## 배경: 작전명 AI("AI" stands for "Actually Individuals"), 코드네임 23 — 다섯번째 미션

[[how-to-read-gpu-model-names|이전 미션]]에서는 그래픽카드 모델명을 읽는 법을 정리했다. 이번 미션은 다시 CPU로 돌아와, CPU가 내부에서 어떤 구조로 명령어를 처리하는지 살펴본다.

CPU는 컴퓨터의 중앙 처리 장치다. 메모리에 있는 명령어와 데이터를 가져와 해석하고, 필요한 연산을 수행한 뒤 결과를 다시 저장한다. 겉으로는 작은 칩 하나처럼 보이지만 내부에서는 제어장치, ALU, 레지스터, 캐시가 역할을 나눠 움직인다.

![CPU 내부 구조 — 제어장치, ALU, 레지스터, 캐시, 메모리|800](/assets/posts/cs/cpu-structure/CPU_structure.png)

이 이미지는 CPU 내부의 핵심 구성 요소와 메모리 사이의 데이터 흐름, 그리고 명령어 실행 흐름을 한 장으로 요약한다.

## CPU가 하는 일

CPU의 기본 작업은 세 단계로 정리할 수 있다.

| 단계 | 의미 |
|------|------|
| 가져오기(Fetch) | 메모리에서 실행할 명령어를 읽어 온다 |
| 해석(Decode) | 명령어가 어떤 작업을 요구하는지 판단한다 |
| 실행(Execute) | 연산, 데이터 이동, 저장 같은 실제 작업을 수행한다 |

프로그램은 결국 명령어의 묶음이다. CPU는 이 명령어를 하나씩 가져와 해석하고 실행한다. 이 흐름이 빠르게 반복되면서 프로그램이 실행된다.

## CPU 내부의 핵심 구성 요소

CPU 안의 구성 요소는 역할이 분명하다. 이름을 외우는 것보다 각 요소가 실행 흐름에서 어디에 쓰이는지 이해하는 편이 중요하다.

| 구성 요소 | 역할 |
|-----------|------|
| 제어장치(Control Unit) | 명령어를 해석하고 CPU 내부 장치에 작업을 지시한다 |
| ALU(Arithmetic Logic Unit) | 덧셈, 뺄셈 같은 산술 연산과 비교, AND, OR 같은 논리 연산을 수행한다 |
| 레지스터(Register) | CPU 내부에 있는 가장 빠른 임시 저장 공간이다 |
| 캐시(Cache) | 자주 쓰는 명령어와 데이터를 CPU 가까이에 보관한다 |
| 메모리(Main Memory) | 실행 중인 프로그램의 명령어와 데이터를 저장한다 |

제어장치는 명령어의 의미를 판단한다. ALU는 실제 계산을 맡는다. 레지스터는 계산에 바로 필요한 값을 잠깐 담아 두고, 캐시는 CPU가 메모리까지 자주 다녀오지 않도록 중간 저장소 역할을 한다.

## 레지스터와 캐시가 중요한 이유

CPU는 매우 빠르지만 메모리는 그 속도를 따라가지 못한다. CPU가 매번 메모리에서 데이터를 가져와야 한다면 연산 장치는 자주 대기하게 된다. 이 차이를 줄이기 위해 레지스터와 캐시가 필요하다.

| 저장 위치 | CPU와의 거리 | 속도 | 주 용도 |
|-----------|--------------|------|---------|
| 레지스터 | CPU 내부 | 가장 빠름 | 바로 계산할 값 저장 |
| 캐시 | CPU 내부 또는 가까운 위치 | 매우 빠름 | 자주 쓰는 데이터 저장 |
| 메모리 | CPU 바깥 | 상대적으로 느림 | 실행 중인 프로그램과 데이터 저장 |
| 스토리지 | CPU에서 가장 멂 | 가장 느림 | 파일과 프로그램 보관 |

레지스터는 CPU가 지금 당장 계산할 값을 담는 공간이다. 캐시는 최근에 사용했거나 곧 다시 사용할 가능성이 높은 데이터를 담는다. 그래서 같은 CPU라도 캐시 구조와 크기에 따라 실제 체감 성능이 달라질 수 있다.

## 코어와 클럭

CPU 성능을 볼 때 자주 나오는 단어가 코어와 클럭이다.

| 항목 | 의미 | 주의할 점 |
|------|------|-----------|
| 코어(Core) | 명령어를 실행하는 독립적인 처리 단위 | 코어가 많아도 작업이 나뉘지 않으면 전부 쓰지 못한다 |
| 클럭(Clock) | CPU가 작업을 진행하는 박자 | 클럭만으로 CPU 성능을 판단하기는 어렵다 |
| 캐시(Cache) | CPU 가까이에 둔 빠른 저장 공간 | 작업 종류에 따라 성능 차이를 크게 만든다 |

코어가 많으면 여러 작업을 동시에 처리하기 좋다. 하지만 하나의 작업이 여러 코어로 잘 나뉘어 실행되지 않으면 코어 수만큼 빨라지지 않는다. 클럭도 마찬가지다. 클럭이 높으면 한 코어가 빠르게 움직일 가능성이 크지만, CPU 성능은 코어 구조, 캐시, 메모리 접근 속도까지 함께 봐야 한다.

## 핵심 정리

- CPU는 명령어를 가져오고, 해석하고, 실행하는 흐름으로 프로그램을 처리한다.
- 제어장치는 명령어를 해석하고, ALU는 산술·논리 연산을 수행한다.
- 레지스터는 CPU 내부의 가장 빠른 임시 저장 공간이다.
- 캐시는 CPU와 메모리 사이의 속도 차이를 줄이는 장치다.
- 코어 수가 많다고 모든 작업이 자동으로 빨라지는 것은 아니다.
- 클럭은 중요한 지표지만, CPU 성능을 혼자 설명하지는 못한다.
