# GPU는 왜 병렬 연산에 강한가 — CPU와의 구조 차이와 SIMT 실행 모델

이 인포그래픽 한 장에 CPU-GPU 비교, SM 내부 구성, 메모리 계층, 제조사별 명칭까지 이 글에서 다룰 내용이 요약되어 있다.

## CPU와 GPU, 설계 목표부터 다르다

CPU와 GPU는 둘 다 연산을 담당하는 시스템반도체지만 다이 면적을 쓰는 방식이 반대다. CPU는 제어 로직과 캐시에 면적 대부분을 쓰고, GPU는 ALU(연산 유닛)에 면적 대부분을 쓴다. CPU는 작업 하나를 최대한 빨리 끝내는 지연시간 최소화를, GPU는 작업 전체를 최대한 많이 동시에 끝내는 처리량 극대화를 목표로 삼는다.

| 구분 | CPU | GPU |
|------|-----|-----|
| 다이 면적 비중 | Control·Cache 위주 | ALU 위주 |
| 코어 수 | 수 개 ~ 수십 개 | 수천 개 |
| 코어 하나의 성능 | 강력함(분기 예측, OoO 실행) | 단순함 |
| 캐시 | 크고 다단계(L1/L2/L3) | 작음, 공유 자원 |
| 강점 | 복잡한 제어 흐름, 순차 처리 | 동일 연산의 대량 병렬 처리 |
| 설계 목표 | 지연시간(Latency) 최소화 | 처리량(Throughput) 극대화 |

## SIMT와 워프 — 명령어 하나로 수천 스레드를 묶는다

커널(kernel)이 실행되면 GPU는 작업을 수천~수백만 개의 스레드로 쪼갠다. 스레드 하나는 데이터 원소 하나(예: 배열 인덱스 하나)를 담당한다. 스레드마다 명령어를 가져오고 해석하는 회로를 따로 두면 다이 면적이 감당되지 않는다. 그래서 GPU는 스레드를 하드웨어 단위로 묶어 하나의 명령어 디코드 결과를 여러 스레드가 함께 쓰게 한다.

이 묶음이 워프(Warp)다. NVIDIA GPU에서 워프 크기는 32로 고정되어 있다. SM 내부 실행 유닛 개수, 레지스터 파일 대역폭 같은 하드웨어 설계에 맞춰 정해진 값이라 소프트웨어가 바꿀 수 없다. 워프 스케줄러는 매 사이클마다 명령어 디코더 하나를 32개 스레드가 공유하게 해서, 디코드 회로 하나로 32배의 처리량을 낸다. 이것이 SIMT(Single Instruction, Multiple Thread) 모델이다 — 명령어는 하나지만 그 명령어를 처리하는 스레드는 32개다.

워프 안의 스레드는 항상 같은 명령어를 같은 사이클에 실행하는 락스텝(lockstep) 방식으로 움직인다. 스레드를 하나씩 독립적으로 스케줄링했다면 지금 수준의 코어 밀도는 나오지 않았을 것이다.

### 워프 분기(Warp Divergence)의 실제 비용

워프가 락스텝으로 움직이면 조건문에서 비용이 발생한다.

```
if (조건) {
    A;   // 스레드 0~15가 참
} else {
    B;   // 스레드 16~31이 거짓
}
```

하드웨어는 스레드마다 다른 명령어를 동시에 실행할 방법이 없다. 그래서 워프는 참 경로(A)를 먼저 실행하며 거짓인 16개 스레드를 놀리고, 그다음 거짓 경로(B)를 실행하며 참인 16개 스레드를 놀린다. 이를 워프 분기(Warp Divergence)라 부른다. 원래 1번이면 끝났을 실행이 2번(A + B)으로 늘어난다. 워프가 갈라지는 경로 수만큼 사이클이 늘어나는 구조다.

코드만 봐서는 이 비용이 드러나지 않는다. GPU 코드를 짤 때 연속된 32개 스레드(워프 하나)가 같은 분기를 타도록 조건을 배치하는 이유가 여기에 있다.

스레드가 코드 상에서 다뤄지는 계층은 다음과 같이 쌓인다.

| 단위 | 설명 |
|------|------|
| 스레드(Thread) | 가장 작은 실행 단위, 데이터 하나를 처리 |
| 워프(Warp) | 스레드 32개를 하드웨어가 묶어 스케줄링하는 단위 |
| 스레드 블록(Thread Block) | 워프 여러 개의 묶음, 하나의 SM에서 실행되며 공유 메모리를 함께 씀 |
| 그리드(Grid) | 스레드 블록 전체의 묶음, 커널 하나를 실행할 때 생성 |

## SM 내부 구조와 제조사별 비교

SM(Streaming Multiprocessor)은 워프가 실제로 실행되는 연산 장치 묶음이다. 같은 스레드 블록에 속한 스레드는 하나의 SM 위에서 실행된다. 아래는 NVIDIA를 기준으로 그 내부를 펼친 구성이다.

| 구성 요소 | 역할 |
|-----------|------|
| 워프 스케줄러 | 매 사이클마다 실행 준비된 워프를 골라 실행 유닛에 배정 |
| CUDA Core | 일반 산술 연산 전담, 개수가 가장 많음 |
| Tensor Core | 행렬곱-누산(MAC) 전담, 딥러닝 연산 가속 |
| L1 캐시 / 공유 메모리 | SM 내부 온칩 자원, 블록 단위로 공유 |

### SM은 메모리 지연을 어떻게 숨기나

SM 하나에는 워프 스케줄러가 여러 개 있고, 동시에 수십 개의 워프를 대기 상태로 들고 있을 수 있다. 워프 A가 글로벌 메모리 접근으로 수백 사이클을 기다리면, SM은 이미 준비된 워프 B, C를 실행 유닛에 채워 넣는다. CPU가 캐시 미스 한 번에 파이프라인이 멈추는 것과 달리, GPU는 대기 중인 워프를 대량으로 쌓아두고 전환하는 방식으로 지연시간을 처리량 뒤로 숨긴다(latency hiding). SM에 동시에 상주할 수 있는 워프 수(occupancy)가 높을수록 이 은닉 효과가 커진다.

이 SM에 해당하는 상위 묶음과 실행 단위의 이름은 제조사마다 다르다.

| 계층 | NVIDIA | AMD | Intel | Apple |
|------|--------|-----|-------|-------|
| 상위 묶음 | GPC → TPC | Shader Engine | Render Slice | 비공개 |
| 실행 단위 | SM | CU / WGP | Xe-core | GPU 코어 |

이름과 세부 구조는 다르지만, 병렬 연산 단위를 묶어 처리량을 높인다는 목적은 같다. NVIDIA·AMD·Intel은 독립형 그래픽카드로 판매되는 반면, Apple은 M 시리즈 칩에 GPU를 직접 통합해 별도 카드 없이 Metal API로 프로그래밍하며, CPU와 메모리를 공유하는 UMA(Unified Memory Architecture) 구조를 쓴다. 2026년 8월 현재 Apple Silicon은 M5 계열까지 확장됐고, M5 Pro·M5 Max에서는 GPU 코어 안에 Neural Accelerator를 넣어 온디바이스 AI 처리 비중을 더 키웠다.

## 메모리 계층

| 메모리 | 접근 범위 | 대략적 지연 시간(사이클) | 관리 방식 |
|--------|-----------|------|-----------|
| 레지스터 | 스레드 1개 | ~1 | 스레드 전용, 하드웨어 자동 할당 |
| 공유 메모리 / L1 캐시 | 블록 1개 | ~20~30 | 공유 메모리는 수동 관리, L1은 하드웨어 자동 관리 |
| L2 캐시 | 칩 전체(모든 SM) | ~200 | 하드웨어 자동 관리 |
| 글로벌 메모리(VRAM) | 그리드 전체 | ~400~800 | GPU 밖 DRAM |

지연 시간 수치는 세대·제조사마다 다르지만 자릿수 차이는 일관된다. 글로벌 메모리 접근 한 번이 레지스터 접근보다 수백 배 느리다. 행렬곱처럼 같은 데이터를 여러 스레드가 반복해서 읽는 연산에서 글로벌 메모리 접근을 공유 메모리 접근으로 바꾸면, 지연 시간이 400~800사이클에서 20~30사이클 수준으로 줄어든다. GPU 코드 최적화는 접근을 이 표의 위쪽 계층으로 얼마나 끌어올리느냐의 문제다.

## 핵심 정리

- CPU는 제어 로직과 캐시에, GPU는 ALU에 다이 면적을 집중한다. 목표는 각각 지연시간 최소화와 처리량 극대화다.
- GPU는 스레드마다 디코드 회로를 두는 대신 32개씩 워프로 묶어 명령어 디코더 하나를 공유시킨다. 이것이 SIMT 모델이 코어 수천 개를 관리 비용 없이 굴리는 방법이다.
- 워프는 락스텝으로 움직이기 때문에 조건문에서 경로가 갈리면(Warp Divergence) 경로 수만큼 실행이 순차적으로 늘어난다. 워프 내부가 같은 분기를 타도록 코드를 짜는 것이 실질적인 성능 튜닝 포인트다.
- 실행 단위는 스레드 → 워프 → 스레드 블록 → 그리드로 쌓이고, SM이 이를 물리적으로 스케줄링한다.
- SM은 워프를 대량으로 대기시켜 두고, 한 워프가 메모리를 기다리는 동안 다른 워프로 실행 유닛을 채운다(latency hiding). GPU가 처리량을 극대화하는 방식은 지연을 없애는 게 아니라 지연이 보이지 않게 채워 넣는 것이다.
- SM(NVIDIA 기준) 안에는 CUDA Core와 Tensor Core가 역할을 나눠 맡는다. 실행 단위 이름은 제조사마다 다르지만(AMD의 CU/WGP, Intel의 Xe-core, Apple의 GPU 코어) 병렬 연산 단위를 묶어 처리량을 높인다는 목적은 같다.
- Apple은 독립형 그래픽카드 없이 M 시리즈 칩에 GPU를 통합하고, UMA로 CPU와 메모리를 공유한다. 2026년 8월 기준 최신 M5 계열은 GPU 안의 AI 가속 구조도 강화했다.
- 메모리는 레지스터 → 공유 메모리/L1 → L2 캐시 → 글로벌 메모리 순으로 범위가 넓어지고 지연 시간은 자릿수 단위로 늘어난다(~1 → ~20~30 → ~200 → ~400~800 사이클). 접근을 상위 계층으로 끌어올리는 것이 GPU 코드 최적화의 핵심이다.
